## Context

A services business that runs projects and rents out equipment needed one admin platform for the whole chain: sales and quotations, projects and jobs, equipment and assets, warehouses and stock, purchasing, and staff. Before a project starts, a proposal is accepted and handed off into a project workspace, and from there the team reserves equipment, crew and locations.

## What I owned

I am the only frontend developer on this platform. I built all 72 screens between August 2025 and September 2026, along with the layers they share: the API client, the state patterns, the table and filter components and the form controls.

## Scope

The platform covers about 65 business entities. Each has the same set of parts: a Redux slice, a hook that wraps it, a list page, create, edit and view dialogs (93 in total), and a filter drawer (36 in total). Every page is lazy-loaded, so the first load does not carry the whole admin.

## Key decisions

### A shared CRUD layer

The first entities were written by hand, and each one repeated the same list, detail, create, edit and delete logic and attached its own auth headers. I replaced that with a slice factory that generates those async actions, the pagination state and memoized selectors. A shared API client attaches the token and signs the user out on a 401. New entities start from the factory, and older ones are moved over to it whenever they are touched.

### Server-side tables

Lists can be long, so paging, sorting and searching happen on the server. One table hook owns that state and builds the request for the backend. A shared data table renders it, as numbered pages or as infinite scroll, and turns rows into cards on small screens. A shared filter drawer holds each list's filters. Because every list page uses these same parts, they all behave alike.

### The API contract

Every endpoint path goes through a helper that checks it against the OpenAPI specification when the module loads, so a typo or a renamed endpoint fails at once instead of in production. Endpoints the backend does not offer yet are declared as such and refused before any request is sent. An audit script fails the build if any source file uses a path that is missing from the specification.

### Weight and layout

Spreadsheet import and export and the rich-text editor are heavy, so they load only when a screen needs them, and vendor code is split into stable chunks. A Playwright audit takes screenshots of the key routes at several viewport sizes in both themes, so layout regressions show up before release.
