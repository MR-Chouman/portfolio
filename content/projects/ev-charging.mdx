## Context

An electric vehicle charging operator also sells batteries and mobile services, and it needed an admin platform for all of it: users and companies, products, bundles and prices, charging stations and plans, vans, drivers and shifts, stock, promotions, orders, branch schedules and the content of its mobile app.

## What I owned

I led this frontend from December 2025 to June 2026, and I wrote about 80% of its commits. I designed the data layer and the list and detail patterns that the screens are built on, and I built most of the screens. Another developer added some of the pages.

## Scope

The 125 screens fall into three kinds. Hub pages group a domain into cards. List pages are the most common kind. Detail pages show a single record with its related actions. Behind them, the API layer has 50 modules, one for each business entity.

## Key decisions

### One API, fifty modules

All the API modules are injected into a single RTK Query API that shares one base query (bearer auth, sign-out on a 401) and one list of cache tags. Each module has the same shape:

- it cleans its parameters
- a mapper turns backend rows into camelCase frontend objects, so components never touch raw backend fields
- it offers list, detail, create, update and delete
- it tags its cache so a change refreshes only what it affects, and only when the change succeeds

### Feedback in one place

A middleware watches every mutation and shows a success or error toast, working out the verb from the endpoint's name. The backend sometimes reports an error inside a successful HTTP response, and the middleware catches that case too. For form errors it also highlights and focuses the field at fault in the open dialog, so no screen has to wire up its own messages.

### The URL holds the filters

Filters and paging live in the URL query string, which makes every filtered list shareable and lets the back button work as expected. Active filters show up as removable chips, and each chip resolves its label from the record's ID.

### Reusable pickers

There are 35 dropdowns for picking related records, and all of them come from one generic component. Each is searchable and scrolls through results page by page. A preselected value that is not on the current page is fetched by its ID, so it still shows its name.
